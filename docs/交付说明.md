## 一、如何运行

### 本地启动
```bash
cd app
python -m http.server 8765
# 或任意静态文件服务器（需支持 .js/.css 正确 MIME）
```
浏览器打开 `http://localhost:8765/` 即可。首次打开自动建库（IndexedDB `eatg_db`，12 个 objectStore）并播种枚举值与 5 个种子角色。

### 数据清除
浏览器 F12 → Application → IndexedDB → 删除 `eatg_db`，刷新即可从零开始。或用「数据管理 → 恢复」导入空备份。

## 三、核心业务口径实现

### 金额（§8）
- 一律以「分」整数存储；展示层 `yuanToCents` / `centsToYuan` 换算，`Math.round` 消除浮点误差。
- `fmtMoney(amount, currency)` 统一汇率换算（JPY→CNY 走 `settings.exchange_rate.rate`）。

### 邮费分摊（§3）
- **per_item**：`floor(S × qty / T)`，尾差并入最后一件。
- **by_amount**：按本体金额占比，要求所有件单价已知（否则阻止并提示）。
- **manual**：合计 > 邮费则阻止；< 邮费则尾差并入最后一件并提示。
- **none**：各件 `shipping_share=0`，订单邮费仍计入全局邮费合计。

### 盈利（§4）
- `实收 = 单价×数量 − 手续费 − 卖家邮费`
- `盈利 = 实收 − 购入成本（本体+邮费分摊）`
- 三档严格区分：`filled` 计入已实现盈利；`estimated` 单列估算盈利；`unknown` 不计盈利。

### 状态机
`deposit_pre → full_pre → shipping → on_hand → sold_out`，回退需二次确认。

### 删除级联（§11）
删除谷子款级联清理购入记录、卖出记录、行情记录；所有删除操作二次确认。

## 四、全局特性（第12步）

### 深色模式（P-03）
- `html[data-theme='dark']` 全站 CSS 变量切换（`main.css` L40+）。
- 设置 → 外观 → 主题：跟随系统 / 浅色 / 深色，切换即生效并持久化（localStorage + IndexedDB）。
- `index.html` head 内联脚本提前应用主题，避免白屏闪烁。

### 启动性能（P-01）
- `initDB()` 异步执行，不阻塞首屏渲染；`render()` 在 `initDB` 之前调用。
- `agg.buildModel()` 将聚合结果写回 `goods.agg` 缓存（best-effort，不阻断渲染）。
- 首屏骨架屏 `#boot-skeleton` 在页面挂载后移除。

### 错误处理（P-07）
- `initDB` 失败：Toast 提示「数据层初始化失败…」，不阻断界面。
- 页面挂载异常：`app.js` render 中同步 try/catch + 异步 `.catch`，Toast 提示。
- 损坏备份导入：`JSON.parse` try/catch → Toast「文件解析失败」。
- 恢复校验：`app==='eatg'` 且 `version<=1`，否则拒绝。
- IndexedDB 不可用：启动检测并 alert。

### 隐私（P-06）
- 全代码库无 `fetch` / `XMLHttpRequest`，无任何上传请求。
- 图片经 `compressImage({ stripExif:true })` 剥离 EXIF 后 base64 存 IndexedDB。

### v1.1.1 新增（图鉴清单导入 + 在线更新）

1. **导入图鉴清单**：图鉴页右上「导」按钮 → 选择本地 `.json` 清单文件（格式 `eatg-gallery-seed`）→ 按角色合并去重（同角色同名跳过，不覆盖已标记的拥有状态/关联谷子）→ 批量写入。清单示例：`app/data/gallery_seed_soyo.json`（素世 61 款草稿）。
2. **在线检查更新**：同一面板可填清单地址（默认仓库 raw 地址），拉取最新清单增量合并。**私有仓库拉取会失败**，需改用本地导入；仓库公开后可在线更新。
3. 角色不存在时自动创建（IP 取清单 `ip` 或 MyGO）；导入条目带 `goods_type/price_jpy/source/source_url/jp_name/image` 扩展字段，编辑保存时保留。
4. **图鉴图片（照片为主）**：素世清单 61 款中 **54 款已配武士道官方商品图**（2026-10-14 抓取官方商店 CDN，含 `source_url` 直达商品页、`jp_name` 官方日文名）；7 款历史款（千岛/外部：2024夏日Q版立牌、长条吧唧vol.5、A咖马口铁徽章、航海ver毛绒吧唧、2024夏日正比大吧唧、GSC粘土人#2873、Zero gravity手办）官网已下架暂无官方图，可自行在图鉴编辑页上传实物照。
5. **补图机制**：已导入过旧版清单（无图）再导入带图清单时，同名条目只补缺失的图/元数据，**绝不覆盖你的拥有标记与关联谷子**；导入结果提示"新增/补图/跳过"三类数字。
6. **谷子库 → 图鉴 自动同步**：打开图鉴页自动执行——谷子库中关联了当前角色的谷子，若图鉴无同名条目则自动添加并关联 `goods_id`（拥有状态随之按谷子购入状态自动点亮：现货→已拥有、预售/在途→半亮）。只添加不存在的，同名多件不重复，不覆盖既有标记；其他角色谷子不混入。
7. **拖动排序**：图鉴工具栏「排序」进入排序模式（仅平铺视图）——长按卡片 380ms 激活拖动、跟手换位，松手按新顺序全量写回 `sort_order`（0..n-1），其余未排序条目自动排后。排序在分组/点亮/刷卡模式下收起，避免误操作。
8. **按品类分组**：分组按钮循环切换「平铺 → 按系列 → 按品类 → 平铺」。按品类按条目 `goods_type` 分组（吧唧/立牌/挂件/纸片/娃娃…），无品类归「未分类」，组内保持手动排序。

## 九、拍照批量录入（离线 OCR）

### 能力
- 拍/选一张照片 → 「自动识别」用**内置 Tesseract.js 离线 OCR**（无外链）识别全图文字区，按「块-段」聚合成 N 个框（最多 9 个）。
- 框可**拖动 / 缩放 / 双击新增 / 选中删除**手动修正。
- 「生成录入」逐框裁剪 → OCR → 命中关键词自动预填**名称 / IP / 类型 / 角色**，跳转批量确认页核对后一键保存。
- 名称默认 = 角色 + 类型；IP / 类型会优先映射到你已配置的枚举（如 `BanG Dream` → 「邦邦」、`バッジ缶` → 「徽章（吧唧）」），未命中则填规范中文名，均可手改。

### 关键词词表（`js/batch_scan.js` 的 `TYPE_SYNONYMS` / `IP_SYNONYMS`）

### 手工验证步骤
1. 新增谷子页 → 点「拍照批量录入」→「相册 / 拍照」选一张带吊牌/包装文字的照片。
2. 点「自动识别」→ 等待进度条（首次约 8~15 秒：加载核心 + 语言包）→ 画面出现 N 个文字框与「已识别 N 个文字区」提示。
3. 拖动/缩放框修正，或双击空白处手动加框，选中后「删选中框」。
4. 点「生成录入」→ 跳转批量确认页，逐条核对预填的名称 / IP / 类型 / 角色 →「全部保存」。

### 需自训练模型清单（本期未做，预留扩展点）

| 目标 | 用途 | 建议方案（保持离线、不新增外链） | 需你准备的数据 | 接入位置 |
